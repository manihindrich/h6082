# Overview

## h6082
**A start page made of markdown: fast, compact, your own.**

Every file `content/pages/*.md` is one tab. `#` starts a column, `##` a block, and inside go links, notes, tasks, service status or RSS.

No database, no build step. A saved file shows up in the open page right away. Content can also be edited in the browser. The look is set in a single TOML file. It all runs in one small container and the browser loads nothing from foreign servers.

## Features
### Content
- tabs as md files, columns and blocks
- full markdown: tables, callouts, tasks, code
- own images from the `content/media/` folder
- web editor with autosave
- version history with diff and restore
- notes and tasks editable right on the page
### Live widgets
- instant refresh after saving
- service status (HTTP, TCP) right next to links
- RSS and server stats as blocks
### Look
- 12 themes and an auto mode following the OS
- UI and documentation in English and Czech
- layout, font and colours in `config.toml`

## Theme
{{theme}}

The choice is saved to `config.toml` (`[theme] default`) and applies everywhere. Requires the editor password. Add your own theme to [config.toml](/edit/config.toml) as a `[themes.<name>]` section:
```toml
[themes.mine]
label  = "mine"
scheme = "dark"
accent = "#ff79c6"
```
Missing colours are taken from the obsidian theme. All keys are described in the [configuration](/docs).

## Language
{{lang}}

The language of the UI and the built-in pages is saved to `config.toml` (`[page] lang`). Requires the editor password. Your own tab `name.md` can get a translation `name.cs.md` or `name.en.md`, shown according to the selected language.

# Content

## My files
{{files user}}

*view* opens the tab, *edit* the editor (*edit cs* for a translation). Rename and delete are in the editor's bar. Deleting moves the file and its translations to `content/.trash/`.

### New file
{{newfile}}

Creates `pages/<name>.md` from a template and opens it in the editor. Create a translation as `<name>.cs`.

## System files
{{files system}}

This page and the documentation come with the application and update with it. Saving one in the editor creates your own copy in `content/system/` (marked *customised*); the *reset to default* button in the editor drops it. The configuration is yours and an update never changes it.

## Editor
- saves itself ~0.8 s after the last change
- ++ctrl+s++ saves at once, ++ctrl+b++ / ++ctrl+i++ format, all shortcuts are in the [config docs](/docs)
- live preview on the right, the divider moves and the preview can be hidden
- rename and delete a file from the bar
- never overwrites a file changed elsewhere (vim, git)
- saves broken TOML, but the last valid config stays in effect
- **history** shows the file's versions, diff and restore
- access is protected by the password from `.env`

# Operation

## Installation
```bash
cp .env.example .env
# into .env: UID and GID (id), editor password
openssl rand -base64 24
docker compose up -d --build
```
Then open <http://127.0.0.1:8088>. The port and other local settings are in `.env`.

## Maintenance
Content and config take effect right after saving.
An update replaces only the application: `content/` and `.env` are never touched.
```bash
# update the application
git pull && docker compose up -d --build
# log
docker compose logs -f h6082
# backup (data + settings)
tar czf h6082.tgz content/ .env
# uninstall
docker compose down --rmi local
```

## How it works
1. the server reads `pages/<tab>.md` (or the translation for the language)
2. splits the text into columns and blocks
3. renders the markdown and caches the result
4. on a file change it notifies open pages (SSE)

# Security

## Security
### Protection
- listens on `127.0.0.1` only
- the editor and every write (notes, tasks, theme, language) are protected by a password (`H6082_EDITOR_PASSWORD` in `.env`)
- runs only its own scripts (CSP). `<script>` and `javascript:` in md do not work.
- foreign sites cannot frame the page, read it via DNS rebinding or call the API
- the container has a read-only file system, no extra privileges and memory and process limits
- checks and RSS go only to addresses from md files
- writes are atomic, deleting is just a move to the trash
- images are sent with CSP `sandbox`, so a script in an SVG never runs
- fonts are verified via SHA-256 at build time

### Recommendations
- **anyone who can see the page can read the md content.** Passwords, tokens and private addresses do not belong there.
- `.env` contains the password and does not belong in the repository (it is in `.gitignore`)
- expose the page to a network only through a reverse proxy with HTTPS and add the server name to `[api] allowed_hosts`
- write e-mail addresses as `{{email name domain}}`, bots cannot read them then
- **hidden tabs are not private.** They are reachable via `/<name>` and listed here on h6082.
- **the password protects writes only, anyone who reaches the page can read it.** On a public server put the whole site behind a login in the reverse proxy.
- server stats (`/api/sys`) are disabled (`[system] enabled`). Examples use `{{sys demo}}` with made-up data. Enable it only where server data does not matter.
- use `{{history demo}}` in examples, the real history shows file names and edit times
- the history keeps deleted text as well. If you accidentally paste a secret into a file, delete the file's history too via **history** in the editor.

> [!info] Left out on purpose
> Host processes, docker containers and the network. They would need a weaker container isolation.
